# Оптимизация XLM-RoBERTa-base для обнаружения финансового фишинга на ESP32-S3

## 1. Постановка задачи

Цель: запуск нейросети для обнаружения мошеннических финансовых SMS ограниченными вычислительными ресурсами (рассматривается бинарная классификация).
Основной сценарий - обнаружение сообщений, имитирующих уведомления банков, платёжных систем и брокеров с целью получения конфиденциальной информации или перенаправления пользователя на мошеннические ресурсы. Практическая ценность в том, что это автономная классификация сообщений непосредственно на устройстве, без передачи текста на внешний сервер. На первом этапе сообщения будут поступать с компьютера через USB.

### Исходная Teacher модель 

В качестве исходной модели выбрана [XLM-RoBERTa-base](https://huggingface.co/FacebookAI/xlm-roberta-base). Это многоязычная Transformer Encoder-модель, поддерживающая русский и английский.

Для классификации финансовых SMS модель будет дообучена с классификационной головой.

| Характеристика | Значение |
|---|---|
| Архитектура | Transformer Encoder |
| Количество параметров | ~278 млн |
| Transformer layers | 12 |
| Hidden size | 768 |
| Attention heads | 12 |
| Intermediate FFN size | 3072 |
| Vocabulary size | 250 002 |
| Maximum position embeddings | 514 |
| Attention mechanism | Multi-Head Self-Attention |
| Задача | Бинарная классификация SMS |

Основные компоненты архитектуры:

- **Tokenizer и Embedding** — преобразование текста в векторные представления.
- **Multi-Head Self-Attention** — моделирование зависимостей между токенами.
- **Feed-Forward Network** — нелинейное преобразование представлений.
- **Layer Normalization** — нормализация промежуточных представлений.
- **Classification Head** — предсказание класса сообщения.

Основная вычислительная нагрузка приходится на матричные умножения в attention и FFN.

Для self-attention вычислительная сложность взаимодействий между токенами растёт квадратично с длиной последовательности. Для FFN существенную роль играют размер скрытых представлений и количество слоёв.

## 2. Целевая аппаратная платформа

**ESP32-S3-WROOM-1-N16R8** — микроконтроллер Espressif Systems с ограниченными вычислительными ресурсами.

| Характеристика | Значение |
|---|---|
| CPU | Dual-core Xtensa LX7 |
| Архитектура | 32-bit |
| Частота | До 240 МГц |
| Internal SRAM | 512 КБ |
| External PSRAM | 8 МБ, Octal SPI |
| Flash | 16 МБ, Quad SPI |
| ROM | 384 КБ |
| GPU / NPU | Отсутствуют |
| Векторные инструкции | Поддерживаются |
| Среда разработки | ESP-IDF |
| Библиотека инференса | ESP-DL |

Основные аппаратные ограничения:

- **SRAM (512 КБ)** — небольшой объём быстрой оперативной памяти для вычислений и рабочих буферов.
- **PSRAM (8 МБ)** — дополнительная оперативная память с потенциально более высокой задержкой доступа.
- **Flash (16 МБ)** — ограниченный объём постоянного хранения модели и прошивки.
- **CPU (240 МГц)** — ограниченная вычислительная производительность по сравнению с GPU.
- **Отсутствие GPU/NPU** — необходимость выполнять операции нейросети на CPU с использованием доступных векторных инструкций.

### Оценка требований исходной модели к памяти

Объём весов модели оценивается по формуле:

**M_weights = N_parameters × bytes_per_parameter**

Для XLM-RoBERTa-base (~278 млн параметров):

| Формат | Байт на параметр | Объём весов |
|---|---:|---:|
| FP32 | 4 | ~1112 МБ |
| FP16 | 2 | ~556 МБ |
| INT8 | 1 | ~278 МБ |
| INT4 | 0,5 | ~139 МБ |

( расчёты не учитывают активации, временные буферы, параметры квантизации и память runtime)
Даже после INT4-квантизации исходная модель значительно превышает доступный объём Flash и PSRAM микроконтроллера, поэтому уменьшения точности весов недостаточно.

## 3. Перечень bottleneck'ов

| Bottleneck | Причина | Последствие |
|---|---|---|
| **Memory Capacity** | ~278 млн параметров, ограниченные Flash и RAM | Исходная модель не помещается на устройство |
| **Computational Cost** | Матричные умножения в Transformer, отсутствие GPU | Потенциально высокая задержка инференса |
| **Memory Bandwidth** | Доступ к внешней PSRAM медленнее внутренней SRAM | Возможное замедление обработки промежуточных тензоров |
| **Tokenization Overhead** | Большой словарь и сложная токенизация XLM-RoBERTa | Дополнительные затраты памяти и вычислений |
| **Runtime Compatibility** | Ограниченный набор поддерживаемых операций ESP-DL | Необходимость адаптации архитектуры |
| **Activation Memory** | Промежуточные тензоры свёрточных слоёв занимают RAM | Ограничение размера входа, числа каналов и batch size |
| **Accuracy Degradation** | Сильное сокращение числа параметров | Риск ухудшения качества обнаружения фишинга |

## 4. Гипотезы по ускорению

### 4.1. Knowledge Distillation

Основным методом оптимизации выбрана дистилляция знаний XLM-RoBERTa-base в компактную символьную свёрточную нейросеть **TinyCharCNN**.

Предполагаемая базовая архитектура Student:

**Input → Character Encoding → Embedding → Conv1D → ReLU → Conv1D → ReLU → Global Max Pooling → Dense → Output**

| Компонент | Конфигурация |
|---|---|
| Максимальная длина входа | 160 символов |
| Размер алфавита | 256 ID |
| Embedding dimension | 16 |
| Conv1D №1 | 64 фильтра, kernel size 5 |
| Conv1D №2 | 64 фильтра, kernel size 3 |
| Pooling | Global Max Pooling |
| Hidden Dense | 32 нейрона |
| Output | 2 класса |
| Batch size | 1 |
| Целевой формат | INT8 |

Предварительное количество параметров Student — **23 778**, или около 23,8 КБ сырых INT8-весов.

По сравнению с XLM-RoBERTa-base число параметров сокращается примерно в **11 700 раз**.

Student предполагается обучать на истинных метках и вероятностных предсказаниях Teacher:

**L = (1 − α) · L_CE + α · T² · L_KL**

Где:

- L_CE — ошибка классификации относительно истинных меток.
- L_KL — расхождение между распределениями Teacher и Student.
- T — температура дистилляции.
- α — вес дистилляционной составляющей.

### 4.2. Статическая INT8-квантизация

Для TinyCharCNN планируется использовать **статическую post-training quantization** с предварительной калибровкой на репрезентативном наборе сообщений.

В качестве основного режима предполагается использовать **W8A8** — INT8-веса и INT8-активации.

Ожидаемые эффекты:

- уменьшение размера весов приблизительно в 4 раза относительно FP32;
- снижение объёма промежуточных активаций;
- сокращение затрат на передачу данных;
- возможность использования оптимизированных целочисленных операций ESP32-S3.

Если PTQ приведёт к значительному снижению качества классификации, дополнительно будет рассматриваться **Quantization-Aware Training (QAT)**.

### 4.3. Pooling Optimization

Предлагается исследовать влияние различных способов pooling на вычислительные затраты и качество TinyCharCNN. Для нашей модели pooling будет применяться к последовательности признаков текста.

В идеях попробовать следующие варианты:

**Global Max Pooling (baseline)**

Для каждого канала выбирается максимальное значение по всей длине последовательности.

Потенциальное преимущество: сохранение наиболее выраженных признаков, например последовательностей символов, характерных для фишинговых сообщений.

**Global Average Pooling**

Для каждого канала вычисляется среднее значение по последовательности.

Потенциальное преимущество: использование информации обо всём сообщении, а не только о наиболее сильном отклике.

**Local Max Pooling**

После первого свёрточного слоя добавляется MaxPooling1D с kernel size = 2 и stride = 2.

Это уменьшает длину промежуточной последовательности приблизительно вдвое, сокращая объём активаций и количество операций последующего свёрточного слоя.

**Local Average Pooling**

Аналогичное уменьшение последовательности с помощью усреднения значений.

Для каждого варианта предполагается измерить:

- macro-F1 и phishing recall;
- число MAC-операций;
- пиковую RAM;
- latency на устройстве;
- размер промежуточных тензоров.

### 4.4. Упрощение архитектуры

Предполагается сравнить варианты Student с 16, 32 и 64 фильтрами, а также исследовать уменьшение размерности embedding и числа свёрточных слоёв.

### 4.5. Оптимизация входной последовательности

Предлагается сравнить максимальную длину входного текста:

- 160 символов
- 128 символов
- 96 символов

Уменьшение длины последовательности позволит сократить число операций и объём промежуточных активаций. 

### 4.6. Оптимизация памяти

Из вариантов:

- повторное использование временных буферов
- минимизация копирования данных
- размещение часто используемых буферов в SRAM
- использование PSRAM для крупных данных
- хранение постоянных весов во Flash
- уменьшение размеров активаций через pooling

## 5. Ожидаемые инженерные компромиссы

| Метод | Ожидаемый выигрыш | Возможный компромисс |
|---|---|---|
| Knowledge Distillation | Значительное сокращение параметров | Возможная потеря качества классификации |
| Замена Transformer на CNN | Уменьшение вычислительной сложности | Ограниченная способность моделировать сложные зависимости |
| Статическая INT8-квантизация | Уменьшение размера весов и активаций | Ошибки квантизации, необходимость калибровки |
| QAT | Возможное восстановление качества после квантизации | Дополнительные затраты на обучение |
| Global Max Pooling | Выделение наиболее сильных признаков | Потеря информации о распределении признаков |
| Global Average Pooling | Более равномерное агрегирование признаков | Возможное ослабление редких, но значимых признаков |
| Local Pooling | Меньше активаций и операций последующих слоёв | Потеря части локальной информации |
| Уменьшение числа фильтров | Меньше операций и параметров | Потеря выразительности модели |
| Сокращение длины текста | Меньше вычислений и активаций | Потеря важных фрагментов SMS |
| Использование SRAM | Потенциально более быстрый доступ к данным | Очень ограниченный объём |
| Использование PSRAM | Увеличение доступной оперативной памяти | Более медленный доступ |

**Основной инженерный компромисс:** сокращение памяти и задержки инференса при сохранении достаточного качества обнаружения мошеннических сообщений.

Для оценки предполагаются следующие целевые показатели:

| Метрика | Предварительная цель |
|---|---|
| Размер Student | ≤256 КБ |
| Дополнительная RAM | ≤512 КБ |
| Latency | ≤100 мс на сообщение |
| Снижение macro-F1 | Не более 2 процентных пунктов относительно Teacher |
| Режим работы | Автономный инференс |
